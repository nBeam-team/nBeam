# nBeam

A solar quotation tool for installers. The installer enters customer
information (or pastes/drops it), the app retrieves rooftop geometry from
the Google Solar API, lets the installer adjust the design on a satellite
view, and produces a printable proposal PDF.

## Features

- **Three input modes** — paste/drop structured data (JSON / CSV / Excel
  TSV), describe the customer in free text (extracted by Gemini with a
  regex fallback), or fill the form by hand.
- **Address-driven roof analysis** — Google Places autocomplete for
  address, Google Solar API for roof geometry, panel candidates, and
  yearly production estimates.
- **Live satellite view** — proposed panel rectangles drawn over the
  Google Maps satellite tile. Toggle to the annual flux heatmap rendered
  client-side from the Solar API GeoTIFF.
- **Live design preview** — adjust panel count, panel wattage, battery
  size, and pricing assumptions; financials recompute as you slide.
- **Regional context** — optional Tavily search snapshot for the
  customer's city (typical electricity prices, PV yield, subsidies).
- **Proposal PDF** — formal multi-section proposal with executive summary,
  property overview (including a Static Maps screenshot of the rooftop),
  line-item costs, financial projection with ROI chart, terms, and
  signature blocks. Generated by the browser's print-to-PDF.

## Tech

- React + TypeScript + Vite
- Tailwind CSS
- Framer Motion, Recharts, geotiff.js
- Google Maps Platform (Maps JS, Places, Solar, Maps Static)
- Tavily search API
- Google Gemini (`gemini-2.5-flash`) for structured extraction

## Prerequisites

- Node.js 20+
- npm 10+
- A Google Cloud project with billing enabled
- A Tavily API key (free dev tier works)
- A Google Gemini API key (free tier works)

## Required Google APIs

In your Google Cloud project, enable:

- **Maps JavaScript API**
- **Places API** (or Places API New)
- **Maps Static API** — needed for the rooftop screenshot in the PDF
- **Solar API**

For production, restrict the keys by HTTP referrer and by API.

## Setup

```bash
git clone https://github.com/pawarsp/nBeam.git
cd nBeam
npm install
cp .env.local.example .env.local
```

Then open `.env.local` and fill in:

```
VITE_GOOGLE_MAPS_KEY=...     # client-side; needs Maps JS + Places enabled
VITE_GOOGLE_SOLAR_KEY=...    # client-side; needs Solar API enabled
VITE_GOOGLE_PLACES_KEY=...   # optional, currently unused
TAVILY_API_KEY=...           # server-side (no VITE_ prefix)
GEMINI_API_KEY=...           # server-side (no VITE_ prefix)
```

The Tavily and Gemini keys deliberately omit the `VITE_` prefix so they
stay out of the client bundle. They are read by the Vite middleware
defined in `vite.config.ts` and injected server-side at request time.

## Run

Development:

```bash
npm run dev
```

Open <http://localhost:5173>.

Production build:

```bash
npm run build
npm run preview
```

## Deployment notes

The Vite middleware proxies (`/api/tavily/search`, `/api/gemini/extract`)
only run during `vite dev`. For a deployed build you need to replicate
those endpoints in whatever hosting environment you choose (Vercel,
Netlify, Cloudflare Workers, or a small Node server). Both endpoints
should:

1. Accept the same JSON request body the client sends.
2. Inject the API key from a server-side environment variable.
3. Forward to the upstream provider.
4. Return the upstream JSON response unchanged.

The frontend uses relative paths to these endpoints, so no client change
is needed.

## Calculations

System sizing and financials live in `src/lib/calc.ts`. The numbers are
deterministic formulas, not LLM output. Indicative German market rates
are used as defaults:

| | Default |
|---|---|
| PV system | €1,000 / kWp installed |
| Battery | €700 / kWh |
| Installation | €2,000 base + €100 / kWp |
| Feed-in tariff | 0.082 €/kWh (overridable per project) |
| Grid carbon factor | 0.38 kg CO₂ / kWh |
| Self-consumption | 30 % without battery, 70 % with battery |
| Electricity inflation | 3 %/yr (overridable per project) |

Production estimates use the matching Solar API panel configuration when
available, falling back to a city-based yield otherwise.
